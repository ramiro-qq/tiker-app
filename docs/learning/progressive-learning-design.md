# 探知：从学习目标到渐进式材料

输入网址是主题识别入口。读取入口正文、页面标题和相关文档链接，按需读取两个子页。结合对话识别知识点；门户、多主题文章或读取失败且没有明确知识点时，先问一个聚焦问题，不直接生成材料。用户补充后结合历史网址重新识别。

确认主题后，将入口资料与官方/技术文档、实践案例、FAQ/常见问题三组检索合并去重。每组保留读取机会，最多八份正文；根据已读页面的链接补充重要子页，不将模型猜测的 URL 当来源。搜索失效或资料不足必须披露。

抓取用 GET 处理公开地址重定向，保存最终地址以正确解析相对链接与引用；不依赖 HEAD 支持。资料阅读后先筛选正文相关性，无关页面不进入教材或参考来源，再规划：目标、前置知识、由浅入深的大纲、必学/选学及原因、可暂缓概念、证据缺口。最终材料按该计划编写，覆盖知识介绍、概念解释、重难点、使用场景、完整案例、练习和总结。默认一份连贯指南，必要时拆为最多五份有阅读顺序的文档；不强制技术代码或固定三个案例。系统单独生成参考来源，引用仅来自实际读取页面。

保持现有 IPC 取消机制、历史材料、归档和同步结构。计划为单次运行数据，不写入同步会话。失败不替换已有材料。模型仍由现有自定义模型选择器决定。

验证：URL 提取和子页筛选、灵活文件验证、空/重复/不安全文件名、计划校验、现有会话及取消回归、Rust 测试和前端构建、焦点样式检查。真实模型生成依赖本机模型凭据，不能以 fixture 代替效果验收。
