# 配置安全、开源模板与 GitHub 同步边界

更新日期：2026-11-21。本文按用户确认的本地存储方案更新：模型信息、状态和 API Key 统一放在本机 `model.json`，整个文件不参与 GitHub 同步。同步连接、账号、Token 和等待时间独立保存在本机 `sync-config.json`；`config.json` 只保留应用设置。此前将模型密钥长期保存在钥匙串、同步模型定义的建议已被本方案替代。

本轮修改了代码、文案、忽略规则和模板说明；没有运行真实用户的钥匙串迁移、修改用户模型/同步文件或上传资料。本次为仓库首次提交前整理，不包含远端历史审计。

## 已确定的存储策略

| 对象 | 保存内容 | 生命周期/同步边界 |
| --- | --- | --- |
| 本机 `model.json` | 模型 ID、名称、Provider、Base URL、模型名称、configured/status、每个模型的 apiKey、defaultModelId | 仅本机；整个文件禁止上传，包括删除 apiKey 后的派生模型配置也不纳入当前同步设计 |
| 模型运行内存 | 当前请求所需的密钥 | Rust 读取本地文件；IPC 响应不包含密钥，不打印到日志 |
| 旧模型钥匙串条目 | 旧版 API Key | 不再读取、迁移或写入；缺少本机密钥时在设置中重新填写，旧条目不自动删除 |
| 本机 sync-config.json | 渠道连接、GitHub 账号、OAuth Token、当前仓库选择、自动同步等待时间 | 仅本机，整个文件禁止上传；目前只实现 GitHub，其他渠道仅预留结构 |
| 旧 GitHub 钥匙串条目 | 旧 OAuth Token 和账号元数据 | 首次实际 GitHub 操作时迁移，成功落盘后不再读取；新授权直接写本地文件，旧条目不自动删除 |
| config.json | 通用偏好、工作区路径、窗口状态、快捷键 | 不整文件同步，仅未来白名单导出可移植偏好 |
| clips.json | 提取设置和运行任务 | 仅本机运行文件；稳定归档另由内容协议处理，不能整文件作为配置上传 |
| learning preferences | 本机 modelId | 仅本机；不含旧要求描述，不因配置同步恢复旧字段 |

编辑模型时 API Key 留空保留现有本机密钥；若本机文件没有密钥，则提示重新填写。所有模型均不再访问模型钥匙串，旧文件内已有明文密钥仍可兼容读取。

文件内的 `apiKey` 字段是唯一的常规模型密钥存储，后端独立提取并仅由磁盘写入函数序列化；普通模型列表、保存结果、测试结果均不返回该字段。无密钥的本地模型用空字符串明确记录，避免再次尝试旧钥匙串。

## 分类与提交规则

| 类别 | 示例 | 公开源码仓库 | 个人私有配置仓库 |
| --- | --- | --- | --- |
| 工程/发行配置 | Vite/Tauri、capabilities、扩展 manifest、公开 OAuth Client ID | 可提交安全配置 | 通常不需要同步 |
| 可移植偏好 | 语言、主题、字号、启动页、兼容快捷键 | 只提交通用默认值 | 未来可白名单同步 |
| 模型配置与凭据 | 整个 model.json、模型定义、状态、默认模型 | 仅无个人数据的空模板 | 不同步 |
| 同步配置与其他身份凭据 | 整个 sync-config.json、GitHub Token、密码、Cookie、私钥、设备码 | 仅空连接模板可提交 | 禁止 |
| 设备状态与权限 | 本机路径、文件授权、窗口尺寸、搜索历史、模型选择、同步基线 | 不提交真实值 | 不同步，本机生成 |
| 业务数据与副本 | 文档、对话、材料、附件、剪藏、备份、冲突内容 | 仅虚构 fixture | 不走配置协议；内容同步独立启用 |

公开源码库和个人私有配置仓库分离。私有仓库也不能存明文凭据。普通偏好“可以同步”不等于默认上传；首次启用仍应预览字段和目标。

新设备自行添加模型和密钥、选择工作区、授权 GitHub。快捷键需做各平台兼容检查；旧 `toggleSidebar` 字段只作本机兼容，不能恢复当前禁止的侧栏展开交互。探知只选择设置中可用的 custom 模型，进入应用仍遵守首个可用 custom 模型的默认规则。

## 现有实现的合理之处

- 内容同步按稳定字段选择，不会扫描上传整个工作区或应用数据目录；模型设置没有进入当前内容同步 DTO。
- GitHub Token 只在后端使用；磁盘连接结构与前端展示 DTO 分开，IPC 不返回凭据。
- 模型与 GitHub 请求不自动跟随重定向，主要服务端错误不回显原始响应秘密。
- 模型密钥不会随前端模型列表返回；用户填写新密钥后通过现有 IPC 传给 Rust。
- 探知偏好只读取 modelId，不继续传递旧要求描述。

## 仍然存在的安全边界

### 本地明文文件的取舍

统一 JSON 消除了新模型和新 GitHub 授权日常使用的钥匙串访问，但密钥在文件中是明文。有权读取该文件的程序可以读取密钥；Unix 文件权限不是针对同一用户进程的隔离机制。

写入使用唯一临时文件、create_new、原子替换，Unix 下创建权限为 0600，减少其他系统用户读取的机会。Windows 使用平台默认文件权限，本轮未新增 ACL 配置。不把文件权限描述为加密。

不加一层把解密密钥也放在同目录的“加密”，这不能有效解决本地秘密保护。模型 API Key 与 GitHub Token 都按用户选择明文保存在仅本机使用的配置文件中。

### 传输和接口地址

当前模型 Base URL 仍接受 HTTP/HTTPS；非本机 HTTP 会明文传输 Bearer Key。配置的服务地址可能是回环 HTTP；不能仅由地址协议判断已发生外网泄露。后续可限制非回环接口使用 HTTPS，本轮未改变网络兼容性。

模型地址仅由本机配置控制；未来配置同步不接受模型定义、任意 headers 或远端默认模型变更，避免将本机密钥发往下载配置指定的服务。

### 内容中的秘密不受配置排除规则自动保护

当前内容同步保留文档、对话、材料、剪藏 URL 和来源 URL。正文中手动粘贴的密钥、签名 URL 和附件中的秘密不会因为 model.json 不上传而自动清除。

当前剪藏 URL 校验禁止 userinfo，但仍允许 query/fragment。建议另做高置信度秘密检测和签名链接检查，不能仅靠 token/apiKey 字段黑名单，也不能粗暴删除所有 URL 参数破坏正常链接。用户不要将运行 model.json 作为普通资料或附件导入同步；本轮没有新增通用内容秘密扫描。

当前同步客户端检查仓库身份和可写性，未强制目标必须私有。未来个人配置同步应在每次写入前检查仓库私有性；公开内容发布需单独授权。本次未访问用户的同步目标或核实其可见性。

### 配置文件混杂和未知字段

AppConfig 多处使用 serde flatten extra 保留未知字段。直接删除 apiKey/token 后上传剩余字段，会漏掉未知或嵌套的敏感内容。

未来建立独立的可移植偏好 DTO，按允许的字段重新构造；不转发 extra、不导出 localStorage 全量、不复制 config.json。导入校验版本、大小、类型、枚举和未知字段，不覆盖文件授权、路径、GitHub 账号、模型选择、自动启用开关或同步基线。

### GitHub 权限和发布保护

当前 OAuth 请求 repo/read:user 范围，应用选择一个仓库不意味着 Token 只拥有这个仓库的权限。未来可评估按仓库安装的 GitHub App 和最小权限；本轮未更改授权流程。

.gitignore 已增加 model.json、sync-config.json、clip-ai.json 及对应临时文件的忽略规则；安全模板使用 *.example.json。忽略规则不影响已被跟踪的文件，也不控制 GitHub API 内容上传；不能以此保证资料正文绝不含秘密。本次已补充 .env 等运行数据忽略规则及暂存区/CI 检查；本机截图和会话材料不纳入源码。

没有 Git 历史、二进制/截图 OCR、WebView 实际存储和远端历史审计，不能宣称完整安全审计通过。如果曾提交真实凭据，先撤销/轮换，再处理历史；删除最新文件无法撤回已传播副本。

## 同步配置拆分与迁移

`sync-config.json` 顶层为 `version/autoSyncDelaySeconds/selectedConnectionId/connections/legacyCredentialPending`。每个连接包含 `id/provider/account/credentials/repository`，GitHub Token 为 `credentials.accessToken`。当前只支持一个 GitHub 连接；结构为未来渠道扩展预留位置，尚无其他渠道实现。

启动时先把旧 `config.json` 的 GitHub 展示快照和 `app.autoRecordInterval` 写入新文件，成功后清理旧字段。已有合法同步文件为准，不因旧快照重写；损坏文件不重置。凭据暂不可用时仍保留账号展示记录。

`load_sync_settings` 只返回无密钥视图，不读钥匙串、不发网络请求。首次实际 GitHub 操作（含已启用的后台同步）按迁移标记读取旧 Token；写入成功后清除标记。拒绝钥匙串授权、账号不匹配或写入失败都保留原文件，允许重试或重新授权。新授权可直接替换旧连接，解除本机授权不会恢复旧钥匙串条目，也不等于撤销 GitHub 服务端授权。

应用设置保存和同步等待时间保存独立，前者无法覆盖后者的账号/密钥。同步配置无法加载时，设置页单独提示并支持重读；本地内容仍可打开。为防止首次迁移失败时丢失旧字段，应用配置保存会要求迁移先成功。

当前仓库选择保存在连接中；每个资料库实际启用的目标、基线、冲突和恢复信息继续位于 `.tiker/sync.json`，不包含 Token。自动同步仍校验连接与资料库目标匹配。

## 模板与未来同步设计

`config/templates/` 已提供当前安全初始模板，model-config 示例始终为空模型列表，不能从真实用户 model.json 脱敏复制。完整字段说明见该目录 README。模板暂未接入自动初始化或运行时导入。

`portable-preferences.proposed.example.json` 是尚未实现的协议草案，仅含通用偏好和兼容快捷键，不含 models/defaultModelId/本机 modelId。旧版建议同步模型定义已撤销。

未来配置同步应单独使用私有仓库、默认关闭，首次预览确认；按字段做三方合并，避免单凭客户端时间戳覆盖其他设备。远端一律视为不可信，导入不触发模型测试、授权、文件读取或插件安装。不同设备的文件权限、密钥和运行基线均独立建立。

任务、内容、文件授权、历史备份、冲突和事务不是初始配置，不为每种运行文件机械复制模板，应由应用安全初始化。新配置字段必须登记默认值、敏感性、是否跨端、迁移方式和本机覆盖规则。

## 验证与限制

模型存储回归覆盖本地 apiKey 持久化及状态保存、IPC 排除密钥、Unix 写入权限、缺少本机密钥时不访问钥匙串、旧文件内联密钥兼容读取、显式替换密钥、空密钥与损坏字段。

同步拆分回归覆盖旧应用字段清理、迁移失败保留字段、账号/Token 重启持久化、迁移只读一次、重新授权覆盖、断开后不复活、坏文件不覆盖、IPC 排除 Token、Unix 0600，以及前端独立保存与失败后重试。

单元测试使用临时配置文件和注入的旧凭据读取边界，不读取用户真实密钥。旧 GitHub Token 迁移仅在实际使用时发生；模型不再从钥匙串迁移。测试不代表已完成用户真实 GitHub 连接迁移。
